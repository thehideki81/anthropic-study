# Study material refresh — 2026-10-16

The study docs were generated on 2026-06-14, with some edits on 2026-06-30. Each key fact was re-checked against the live primary docs: platform.claude.com, code.claude.com (including the Agent SDK pages; platform.claude.com/docs/en/agent-sdk/* now redirects there), anthropic.com/engineering and modelcontextprotocol.io. The exam guide's syllabus is unchanged: 5 domains, 30 task statements, same weights. A dead `docs.anthropic.com` link or an old `/docs/en/docs/...` link (many now 404) was replaced with its current canonical URL.

The cross-domain changes with the most exam impact:

- **Models.** The current models are `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5` and `claude-fable-5-1`. The docs examples now use Opus 5.5 and recommend starting with it "for most workloads". Opus 4.8 is legacy.
- **Forced `tool_choice` (`any`/`tool`).** It now returns **400 on Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1**. The documented replacement is `auto` + `strict: true`, or `output_config.format`. Manual extended thinking (`thinking.type: "enabled"`) also rejects forcing. Adaptive thinking does not reject it, but a forced call skips thinking.
- **Explore subagent.** It now runs on the **main conversation's model, not Haiku**. This reverses a June fact that appeared in D1, D3, D4 and D5.

  - `updatedMCPToolOutput` is no longer labelled deprecated; the docs just prefer `updatedToolOutput`.
  - The default hook timeout went from 60 s to **600 s**. It is 30 s for UserPromptSubmit and the model-switch hooks, and 10 s for MessageDisplay.
  - The TypeScript-only hook event list grew: PostCompact, PermissionDenied, StopFailure, Pre/PostModelSwitch, InstructionsLoaded and others.
- **Sessions.**
  - Resume-by-ID now searches all projects (v2.1.223+), so "resume from the wrong cwd gives a fresh session" only applies to older CLIs.
  - Python persistence can now be suppressed (`CLAUDE_CODE_SKIP_PROMPT_HISTORY`).
- **Effort default.** It is `medium` on Opus 5.5 and Haiku 5.5, and `high` elsewhere.
- **`model_context_window_exceeded`.** It is typed only in the SDK `beta` namespace.

**(b) Added**

- **Tool Runner** (`client.beta.messages.tool_runner`, `max_iterations`) and **Claude Managed Agents** (beta `managed-agents-2026-04-01`).
- **`ResultMessage` subtypes.** New `error_during_execution` and `error_max_structured_output_retries`, plus a `stop_reason` field.
- **Subagent limits and defaults.**
  - 20 concurrent subagents (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`).
  - The budget cap includes subagent spend.

  - Output is marked partial when `maxTurns` is hit.
  - Subagent output is scanned for instruction-shaped text (v2.1.210+).
  - Subagents can message siblings through `SendMessage`.
- **Hook decisions.**
  - The meanings of allow/deny/ask/defer.

## Domain 2: Tool Design & MCP Integration

**(a) Changed**
- **Tool name regex.** It is now `^[a-zA-Z0-9_-]{1,128}$` (was `{1,64}`).
- **Forced `tool_choice`.** It is model-dependent, as described in the cross-domain list above. The "`any` + `strict` guarantees a valid call" tip only holds on models that allow forcing.
- **MCP spec revision.** It is now **2026-07-28** (was 2025-06-18).
  - Input-validation failures are now **tool execution errors (`isError: true`)**, not JSON-RPC protocol errors.
  - Clients SHOULD pass execution errors to the model.
  - `structuredContent` may be any JSON value.
- **Web search error codes.** `invalid_input` is now `invalid_tool_input`, and `request_too_large` was added. The handle-tool-calls page still shows the old name.
- **`.mcp.json` with an unset `${VAR}`.** The config loads with a warning and keeps the literal `${VAR}`; it was "fails to parse".
- **MCP description truncation.**
  - It is now 4,096 characters for server instructions and upfront tools, and 16,384 for tools loaded through tool search (v2.1.296). It was 2 KB.
  - `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` overrides it.
- **MCP scope precedence.** `managedMcpServers` (v2.1.259+) now ranks above local, project and user.
- **Read-before-Edit/Write.** It is relaxed on newer models: edits of an unread file are allowed from v2.1.208, and overwrites from v2.1.228, when reading the file would need no permission prompt. It is still required on Opus 4.6, Haiku 4.5 and older, and for notebooks.
- **Subagent result.** Only the final report returns, and the parent may summarize it. The tool shows as `Agent` in `tool_use` blocks and as `Task` in `system:init`.
- **Tool-use system-prompt token figures.** Opus 5 and Opus 5.5 were added.

**(b) Added**
- **Tool search.** It returns 5 results by default, allows up to 10,000 deferred tools, needs at least 1 non-deferred tool, and needs no beta header.
- **Strict tool use limits.** 20 strict tools, 24 optional parameters and 16 union-type parameters per request. Compiled grammars are cached for 24 h.
- **Programmatic tool calling is GA.** It uses `allowed_callers` and needs `code_execution_20260120`. It is incompatible with strict, forced `tool_choice`, `disable_parallel_tool_use` and MCP connector tools.
- **MCP connector.** Beta `mcp-client-2025-11-20`, `mcp_toolset`, HTTP/SSE only, results come back as `mcp_tool_result` with `is_error`.
- **Glob and Grep.** They are **absent by default on macOS, Linux and WSL**; Claude uses Bash `find`/`grep` instead.
- **define-tools guidance.**
  - "Ask for an explanation, not reasoning" (otherwise a `reasoning_extraction` refusal is possible).
  - Return stable semantic identifiers.
  - `input_examples` limits.
- **MCP spec additions and deprecations.**
  - Deprecated: HTTP+SSE, Roots, Sampling, Logging and Dynamic Client Registration.
  - Tool names are 1–128 characters, and aggregating clients should prefix them.
- **Claude Code MCP additions.**
  - `headersHelper`, `oauth`, `alwaysLoad: false` and elicitation.
  - Project servers auto-load in `-p`/SDK runs.
  - Oversized output is saved to a file above 50,000 characters (`maxResultSizeChars`).
  - MCP prompts run as `/mcp__server__prompt`.
- **Permission rules.**
  - Rules are evaluated deny → ask → allow.
  - A Read deny also blocks Edit/Write on that path.
  - `:*` is equivalent to a trailing wildcard.
- **Read and Bash limits.** Read returns 25,000 tokens per call, refuses whole files over 256 KB, and has `allow_large`. Bash timeout environment variables are now covered.

**(c) Removed / refuted**
- "Config fails to parse on an unset `${VAR}`."
- "2 KB description truncation."
- "Invalid arguments is a protocol error" (2026-07-28 spec).

**(d) Still flagged "reconfirm"**
- The legacy scope names (local was once "project", user was once "global").
- `alwaysLoad` needing v2.1.121+.
- "outputSchema conformance doesn't apply to `isError` results."

## (e) Citations + strict tool use / forced `tool_choice`: the answer

**Citations are documented as incompatible only with JSON outputs, not with strict tool use or forced `tool_choice`.**

- **The documented incompatibility.** The Citations page has the warning "Citations and structured outputs are incompatible". It says that if you enable citations on any user-provided `document` or `search_result` block **and** include `output_config.format` (or the deprecated `output_format`), the API returns **400**. The reason given is that citations interleave citation blocks with text, which conflicts with JSON-schema constraints. The structured-outputs "Feature compatibility" section lists Citations as incompatible with the same `output_config.format` trigger.
  - https://platform.claude.com/docs/en/build-with-claude/citations
  - https://platform.claude.com/docs/en/build-with-claude/structured-outputs#feature-compatibility
- **Strict tool use (`strict: true`).** It is **not** listed as incompatible with citations on the Citations page, the Strict tool use page or the structured-outputs compatibility list. Strict tool use only constrains `tool_use.input`, while citations ride on `text` blocks. Combining them in one request is not a documented error. **It was not tested live** (no API key was available), so it is flagged *reconfirm by test*.
  - https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use
- **Forced `tool_choice` (`any`/`tool`).** It is not documented as an error together with citations, but it has two practical consequences.
  1. With `any`/`tool`, the API prefills the turn so Claude emits **no text before `tool_use`**. The forced turn therefore carries no citations, and the cited answer arrives on the next turn, after the `tool_result`. The search-results docs show this pattern: forced retrieval, then `search_result` blocks with `citations.enabled` inside the `tool_result`, then a follow-up request without `tool_choice` that returns cited text.
  2. On Opus 5.5, Sonnet 5.5, Fable 5.1 and Mythos 5.1, forced `tool_choice` returns 400 by itself, whether or not citations are used.
  - https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools#forcing-tool-use
  - https://platform.claude.com/docs/en/build-with-claude/search-results
- **Design guidance for the exam.** When you need both cited quotes and typed fields, don't add `output_config.format` to the citations request. Instead:
  - get the cited text answer, then extract it to JSON in a second call, or
  - use a strict tool on `auto` with explicit provenance fields (quote, source, location).

  - Domain 5: Task 5.5 key fact; Task 5.6 key fact, ✅/❌ patterns and self-check.
